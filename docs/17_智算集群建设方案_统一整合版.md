# 智算集群建设方案｜统一整合版

> 本文整合用户提供的《智算集群建设方案 v3.2》《GLM-5.3 千卡到 5000 卡智算集群建设方案》《存储与网络架构方案》《骨干环网架构方案》《华为超节点-千卡算存架构方案》和《方案完整评审报告 v3.0》。
>
> **版本原则**：以 v3.2 和 2026-10-10 评审修订后的数据为准；旧版 `TP=16 跨机`、旧网络投资、旧存储带宽和旧能效公式不再作为结论。

## 1. 建设目标与业务边界

建议把建设方案拆成三条业务线：

| 业务线 | 目标 | 主要资源形态 |
|---|---|---|
| 推理服务 | 高吞吐、低延迟、成本可控 | 3:1 收敛、PD 分离、W8A8、Prefix Cache |
| LoRA / 轻量微调 | 参数高效、任务快速闭环 | 机内 TP8、跨机 EP/DP/PP、Checkpoint 快照 |
| 全参预训练/重微调 | 高带宽、低时延、稳定扩展 | 1:1 无阻塞、超节点 UB、8-rail RoCEv2、独立存储面 |

**必须先拍板业务边界**：推理为主和全参预训练对网络收敛比、存储带宽、GPU/NPU 选型和投资的影响完全不同。

## 2. GLM-5.3 BF16 模型基线

按原始模型配置和权重体积实测，参考口径如下：

| 指标 | 数值 |
|---|---:|
| 总参数 | 753.33 B |
| 激活参数 | 41.16 B |
| MoE 专家数 | 256 |
| 每 token Top-K | 8 |
| BF16 权重体积 | 1506.66 GB（约 1403.19 GiB） |
| KV / token | 87.75 KiB |
| 单副本规模 | 16 卡 |
| 单卡权重 | 约 50.2 GB（按 v3.2 重算口径） |
| 单卡可用 KV | 约 69.8 GB |
| 8K 并发 | 约 3035 路 |

> 以上数据用于容量和方案对比，不是对所有业务负载的承诺。上线前必须用实际模型版本、Tokenizer、并行策略、Batch 和 SLO 重新测算。

## 3. 千卡到 5000 卡演进路线

| 阶段 | 时间 | 规模 | 核心目标 | 关键交付 |
|---|---|---:|---|---|
| 一期 | 0～3 月 | 1000 卡 | 能力验证 | 单副本跑通、基线指标、存储和网络最小闭环 |
| 二期 | 3～9 月 | 3000 卡 | 规模与混部 | 训练/推理混部、配额、优先级、Checkpoint |
| 三期 | 9～12 月 | 5000 卡 | 全量生产 | SLA、多租户、成本、慢卡检测、备件和容灾 |
| 目标态 | 后续 | 10240 卡 | 统一算存平台 | 多 POD、统一调度、存储多文件系统和统一命名空间 |

![千卡到 5000 卡演进路线图](assets/compute-1000-to-5000-roadmap.png)

建设原则：

- 一次规划，分期建设；
- 机位、桥架、光纤、电力、制冷按终态预留；
- POD、VLAN、VXLAN、IP、AS、轨道编号一次规划到位；
- 优先在线扩容，避免阶段性返工；
- 每一步都有 POC、压测、故障演练和回滚条件。

## 4. 业务边界与并行策略

### 4.1 正确并行原则

**TP 不跨机走 RoCE；注意力层 TP 在机内或超节点 UB 域内完成。**

推荐：

```text
注意力层：机内 TP8 或 UB 域内 TP
专家层：EP=32 跨 4 节点，all-to-all 走 RoCE
数据并行：DP 跨节点
流水线并行：PP 跨节点
每卡：1 × 400G 承载 EP / DP / PP
```

不适合的做法：

- 把 TP 做成跨机 RoCE；
- 用单机 8 卡强行装下 1403 GiB 的 BF16 权重；
- 把 MoE 专家并行和拓扑不感知的调度混在一起；
- 让所有并行通信都走同一条参数面。

### 4.2 评审修正

评审指出“TP 跨 RoCE 自相矛盾”成立。最初建议“单机 8 卡、TP 上限 8”对 GLM-5.3 BF16 不可行，因为：

```text
单节点显存：8 × 128 GB = 1024 GB ≈ 953.7 GiB
BF16 权重：约 1403.19 GiB
模型无法放入单节点
```

正确修复是：

```text
注意力层 TP=8 在机内或 UB 域内
专家层 EP=32 跨 4 节点
all-to-all 走 RoCE
TP 不跨机走 RoCE
```

## 5. 网络架构

### 5.1 目标态 10240 卡

参考《存储与网络架构方案》：

| 项目 | 规格 |
|---|---|
| 计算节点 | 1280 × 8 卡 = 10240 卡 |
| 物理网络 | 2 张：RoCEv2 + 管理 |
| 逻辑网络 | 3 张：计算 / 存储 / 业务 |
| 收敛比 | 3:1 |
| Leaf | 214 台 × 64 × 400G，48 下行 : 16 上行 |
| Spine | 27 台 × 128 × 400G，3424 上行端口 |
| 400G 光模块 | 27328 个 |
| 下行 / 上行带宽 | 4096 / 1369.6 Tbps |
| 实测收敛比 | 2.99:1 |
| 集团上行 | 2 路 × 1.6 Tbps，eBGP + BFD 双活 |

> 27 台 Spine 端口利用率约 99.1%，几乎无余量。建议按 32 台建设或预留机位、光纤和电口，目标利用率约 83.6%。

### 5.2 统一 Leaf 模型

评审后统一采用 **48 下行 : 16 上行**：

| 规模 | Leaf / Spine |
|---|---:|
| 1000 卡 | 21 / 3 |
| 3000 卡 | 63 / 8 |
| 5000 卡 | 105 / 14 |

这比旧版 `32:32` 更符合标准 Leaf 端口模型，并降低网络投资和端口浪费。

### 5.3 三条逻辑网络

- **计算网**：GPU/NPU 集合通信、参数同步；高优先级；带宽保障 ≥60%；PFC 仅 POD 内。
- **存储网**：并行文件系统、NVMe-oF、Checkpoint；独立 VXLAN；跨 POD 禁 PFC，使用 ECN + DCQCN。
- **业务网**：推理接入、数据加载、管理 API；普通 VLAN/VXLAN，尽力而为。
- 物理管理网：iBMC、Redfish、SNMP、Syslog，独立布线，与生产网隔离。

## 6. 存储架构

![存储与网络架构方案](assets/compute-storage-network.png)

### 6.1 热层、温层、冷层

- 热层：并行文件系统、全闪 NVMe，承载参数、Checkpoint 和训练中间数据；
- 温层：大容量全闪或对象存储，承载数据集、模型版本和近期历史；
- 冷层：对象存储，承载归档、审计和历史快照。

### 6.2 参考规模

| 规模 | 节点 | 热层有效容量 | 读 / 写带宽 | 并行 FS | 温层 / 冷层 |
|---:|---:|---:|---:|---|---:|
| 4096 卡 | 512 | 1.5 PB | 1.0 / 0.5 TB/s | MDS4 / OSS36 / OST432 | 3 PB / 5 PB |
| 10240 卡 | 1280 | 3.5 PB | 2.5 / 1.2 TB/s | MDS8 / OSS96 / OST1152 | 8 PB / 15 PB |
| 20480 卡 | 2592 | 7 PB | 约 5 TB/s | MDS16 级 | 按比例扩展 |
| 41472 卡 | 5184 | 14 PB | 约 10 TB/s | MDS32 级 | 按比例扩展 |

> 存储带宽按单卡 0.2 GB/s 再乘 1.3 安全系数作为工程假设。最终阈值必须以实际数据加载、Checkpoint、重排和混部负载校准。

### 6.3 Lustre 关键点

- MDT：NVMe RAID1，双 MDS 主备，DNE 分命名空间；
- OST：每块 NVMe 一个 OST，禁用 RAID5/6；
- LNet：`o2ib` 绑定 RoCE 网口，多网口多轨；
- 服务端：`brw_size=16M`，`ost_io threads_max=512`；
- Checkpoint：`lfs setstripe -c 32 -S 4M`；
- 数据集：PFL 分层条带；
- 小文件：DoM，目录 `lfs mkdir -c 8`；
- 客户端：`max_rpcs_in_flight=64`，`max_dirty_mb=1024`；
- 直通加速：`mount -o gds`，使用 GPUDirect 或 NPU Direct Storage。

单文件系统不建议无限制扩展。超过数千 OST、数百 MDT 或 5000 客户端后，采用 **多文件系统 + 统一命名空间**。

## 7. 骨干环网

![骨干环网架构方案](assets/compute-backbone-ring.png)

### 7.1 定位

骨干环位于 POD CLOS 之上、集团算力网之下，连接：

- 4 个 POD；
- 存储中心；
- 算力网出口；
- 后续跨园区环。

参考拓扑：6 节点 A/B 双平面环形骨干，每节点双归两台骨干路由器。

### 7.2 关键指标

| 项目 | 规格 |
|---|---|
| 链路速率 | 园区 400G / 800G；跨园区 400G ZR+ |
| 段容量 | 28.8 Tbps（36 × 800G / 段） |
| 环总容量 | 172.8 Tbps |
| 保护倒换 | < 50 ms，TI-LFA FRR + BFD |
| 路由 | IS-IS SRv6 或 eBGP + EVPN |
| 单跳时延 | 约 28 μs（设备 + 5 km 光纤） |
| 正常 / 故障端到端 | 约 84 μs / 约 140 μs |
| 5000 卡 800G 光模块 | 432 个 |

### 7.3 六条硬约束

1. PFC 不跨 POD；骨干用 ECN + DCQCN + 大缓存；
2. A/B 平面物理隔离，避免共因故障；
3. 按故障态设计容量，单链路故障绕行最坏段负载翻倍；
4. 故障绕行时延必须进入 SLA 预算；
5. 参数面、存储面、业务面、管理面隔离；
6. 节点数 > 8 或 ρ 升高时，转为“环 + 平面”混合骨干。

## 8. 华为超节点与千卡算存

![华为超节点-千卡算存架构方案](assets/compute-huawei-supernode.png)

参考配置：

| 项目 | 规格 |
|---|---|
| NPU | 1024 × 昇腾 910C |
| 服务器 | 128 × Atlas 800T A3，8 NPU / 节点 |
| 超节点互联 | 灵衢 UnifiedBus，全光，392 GB/s / 卡 |
| 计算域 | 8 个超节点，每个 128 卡 / 16 节点 |
| 参数面 | RoCEv2 400G，8 轨道，Leaf 32 / Spine 8，1:1 无阻塞 |
| 存储面 | NVMe-oF over RoCE，200G / 400G，专用无损 |
| 业务 / 管理面 | 25G / 100G Ethernet；GE 带外管理 |
| 存储容量 | 高性能 2～4 PB NVMe + 容量 10～20 PB |
| 存储读带宽 | ≥ 1 TB/s |

与 5000 卡集群映射：

```text
4 个超节点 × 1024 卡 = 4096 卡（微调/训练）
+ 1 个推理池约 900 卡（3:1 收敛）
+ 备用卡
≈ 5000 卡
```

并行原则：

- Attention TP 在 UB 域内完成；
- 专家层 EP all-to-all 跨节点走 RoCE；
- DP / PP 走参数面；
- TP 不跨机走 RoCE。

## 9. 评审修订与执行顺序

### 9.1 P0 定案

- P0-1 业务边界拍板；
- P0-2 统一 Leaf 48 下行 : 16 上行；
- P0-3 改为 EP 为主，TP 不跨机走 RoCE。

### 9.2 P1 修正

- 存储带宽口径；
- 能效公式统一：`N_node × 0.3 + 50 kW`；
- 910C 算力统一标注为 400 / 800 并列；
- 存储容量口径；
- 存储网与计算网关系澄清。

### 9.3 P2 补齐

- xlsx 可复算；
- 舍入统一；
- 工程清单；
- 立项 POC；
- 可靠、安全、运维；
- TCO 和成本结论。

建议执行顺序：

```text
P0 业务边界
→ P0 统一 Leaf 48/16
→ P0 改 EP 为主并行
→ P1 全部数字重跑
→ P2 补齐与规范化
```

## 10. 立项 POC 与验收

POC 必须验证：

- GLM-5.3 是否能按目标并行策略加载；
- TP / EP / DP / PP 的真实通信路径；
- RoCEv2 + PFC / ECN / DCQCN 稳定性；
- 存储读带宽、Checkpoint 写入和恢复；
- 参数面 / 存储面 / 业务面隔离；
- 断点续训、慢卡、链路故障和节点故障；
- 能效、功率、液冷、PUE；
- 网络投资、存储投资、GPU/NPU 投资和 TCO；
- 推理 TTFT、TPS、并发和单位 token 成本。
