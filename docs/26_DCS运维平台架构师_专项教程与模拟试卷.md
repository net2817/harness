# AI 运维平台架构师（DCS）专项教程与模拟试卷

> **配套关系**：第 25 章是「JD 解读 + 30 道问答 + 系统设计」，本章是它的**训练手册与考场**——8 周教程、12 个动手实验、3 套模拟试卷（含答案与评分标准）、20 道高频追问。

> **适用对象**：准备字节跳动 DCS / 大厂 AI Infra 运维平台架构岗的候选人；也适合已在岗、需要补齐"硬件 + AIOps + Agent + 知识工程 + 产品化"全链路的工程师。

## 2. 8 周详细教程

> 每周按 **6–10 小时** 设计：2 小时读 + 4 小时动手 + 2 小时写交付物。
> 每周都必须留下**可验证的产物**（脚本、报告、看板截图、复盘），面试时这就是你的项目素材。

### 第 1 周：数据中心与服务器运维基础

**目标**：能说清一台服务器从到货到退役的全生命周期，以及 DCIM/CMDB 在整个运维体系中的位置。

**知识点**

1. 数据中心分层：园区 → 楼栋 → 机房 → 模块 → 机柜 → U 位 → 设备；
2. 服务器生命周期：到货 → 上架 → 配置 → 上线 → 运行 → 维修 → 退役 → 资产处置；
3. DCIM 与 CMDB 的区别：DCIM 管"物理与设施"，CMDB 管"配置项与关系"；
4. BMC / IPMI / Redfish：带外管理的三代接口，Redfish 是当前主流（RESTful + JSON）；
5. 工单与变更：事件（Incident）vs 变更（Change）vs 问题（Problem）。

**动手实验**

- 用 Redfish 读取一台服务器（或模拟器）的资产、电源、温度、风扇信息：

```bash
curl -k -u admin:password https://<BMC_IP>/redfish/v1/Systems
curl -k -u admin:password https://<BMC_IP>/redfish/v1/Chassis
curl -k -u admin:password https://<BMC_IP>/redfish/v1/Managers
```

- 建一张最小 CMDB 表（Postgres）：`device(id, sn, model, rack_id, u_position, bmc_ip, status, owner)`；
- 画一张"设备-机柜-机房-交换机-电源域"的拓扑图。

**交付物**：`week01_cmdb.sql` + 拓扑图 + 200 字总结。

**自检**：能否解释"为什么 CMDB 不准，AIOps 一定不准"？

### 第 2 周：GPU 硬件、固件基线与压测

**目标**：能独立完成一批 GPU 服务器的上线验证，并给出"能否进池"的结论。

**知识点**

1. GPU 架构：SM/CUDA Core、显存（HBM）、NVLink、PCIe、MIG；
2. 国产 GPU：昇腾（达芬奇 + CANN + HCCL）、海光（DCU + ROCm 系）、寒武纪（MLU）；
3. 固件体系：BIOS、BMC、GPU VBIOS、NVSwitch、网卡、SSD、CPLD；
4. 压测工具：`nvidia-smi`、DCGM、`nvbandwidth`、`nccl-tests`、`gpu-burn`、`ib_write_bw`；
5. 慢卡识别：同型号同配置下的带宽/算力/温度/功耗对比。

**动手实验**

```bash
# 1) 健康与拓扑
nvidia-smi -q
nvidia-smi topo -m

# 2) GPU 诊断（需 DCGM）
dcgmi diag -r 3

# 3) P2P / NVLink 带宽
nvbandwidth

# 4) 集合通信（8 卡 AllReduce）
./build/all_reduce_perf -b 8 -e 8G -f 2 -g 8

# 5) 稳定性与功耗
gpu-burn 600

# 6) RDMA 链路
ibv_devinfo
ib_write_bw -d mlx5_0 -a
```

**交付物**：一份《GPU 节点上线压测报告》，包含：机型、固件版本、单卡/多卡/网络带宽、温度功耗、结论（进池/降级/返修）。

**自检**：能否解释"为什么 `nvidia-smi` 利用率 100% 不代表吞吐高"？

### 第 3 周：高功率密度整机柜（供电 + 散热）

**目标**：能对一个 50–150kW 机柜做供电与散热方案计算。

**知识点**

1. 功率分解：GPU + CPU + 内存 + 网卡 + 电源损耗；
2. 供电：传统 PSU vs **PowerShelf（48V/50V DC 机柜级供电）**；N+N 冗余；
3. 散热：风冷 → **冷板液冷** → 浸没；**冷板 + 风冷融合**是当前主流过渡方案；
4. **CDU**（冷量分配单元）与 **SideCar**（侧柜）的作用；
5. 关键指标：PUE、WUE、进液温度、流量、压差、漏液检测；
6. 工程约束：承重、层高、管路、快接头、维护空间、噪声。

**动手实验（计算表）**

| 公式 | 说明 |
|---|---|
| `P_total = P_IT × PUE` | 总设施功率 |
| `年电费 = P_total(kW) × 8760 × 电价` | 年电费 |
| `Q = P / (c_p × ΔT)` | 冷却液流量（水 cp≈4.18 kJ/kg·K） |
| `1 kW ≈ 3412 BTU/h` | 冷量换算 |

**算例**：IT 负载 100kW，PUE 1.25 → 总功率 125kW，年电费（0.6 元/kWh）= 125×8760×0.6 ≈ **65.7 万元**。
80kW 冷板，ΔT=10K → 流量 = 80/(4.18×10) ≈ **1.91 L/s ≈ 6.9 m³/h**。

**交付物**：一份《100kW 机柜供电与液冷方案》Excel（含功率、UPS、CDU、流量、管径、冗余）。

**自检**：能否解释"为什么高密机柜不能只靠提高风扇转速"？

### 第 4 周：互连与 AI Factory

**目标**：能区分 Scale-up 与 Scale-out，并给出铜缆/光互连的选型建议。

**知识点**

1. **Scale-up**：NVLink / NVSwitch（NVIDIA）、HCCS / 灵衢（昇腾），机内或超节点内；
2. **Scale-out**：InfiniBand / RoCEv2，跨机柜、跨机房；
3. 铜缆（DAC/ACC）vs 光互连（AOC/光模块）：距离、带宽、功耗、成本、故障率；
4. 拓扑：rail-optimized、Spine-Leaf、无阻塞 vs 收敛；
5. **AI Factory**：算力、网络、存储、供电、制冷、软件一体化，目标是**单位 token 成本最优**。

**动手实验**

- 用 `nvidia-smi topo -m` 读懂 `NV`/`PIX`/`PHB`/`SYS` 的含义；
- 用 `ibstat` / `ibv_devinfo` 检查 IB 端口速率与状态；
- 画一张"8 卡 HGX + 多机 IB + 存储"的端到端拓扑图，标出每段带宽。

**交付物**：一份《互连选型对照表》（短距/长距、带宽、成本、故障特征）。

**自检**：能否解释"NVLink 为什么不能跨机柜"？

### 第 5 周：AIOps 基础（监控、告警、RCA、容量、变更、自愈）

**目标**：能搭一个最小 AIOps 闭环原型。

**知识点**

1. 监控四件套：Metrics / Logs / Traces / Alerts；
2. 告警收敛：时间聚合、拓扑聚合、因果抑制；
3. 根因分析：规则 + 图 + 统计 + 知识 + LLM；
4. 容量：水位、预测、扩容决策；
5. 变更：分级、审批、灰度、回滚、审计；
6. 自愈：L0–L3 分级与防误操作。

**动手实验**

- 用 Prometheus + node_exporter 采集一台机器指标；
- 写一个告警收敛脚本：把同一机柜 5 分钟内的 50 条告警聚合成 1 个事件；
- 用 CMDB 拓扑做"共同祖先"查询（Redis/Postgres 均可）。

**交付物**：告警收敛前后对比报告（数量、MTTD、误报率）。

**自检**：能否说出"告警收敛"和"告警抑制"的区别？

### 第 6 周：Agent 平台（Harness + MCP + 编排 + 评测 + 治理）

**目标**：能搭一个"查告警 → 查知识 → 给建议 → 人工审批 → 执行"的最小 Agent。

**知识点**

1. Harness 四件事：上下文、工具、状态、恢复；
2. MCP：Tools/Resources/Prompts、stdio vs Streamable HTTP；
3. 工具设计：单一职责、Schema、超时、幂等、权限；
4. 编排：单 Agent 优先，多 Agent 仅用于上下文压力/交叉验证；
5. 评测：Golden Set + 回归门禁 + 线上指标；
6. 治理：模型准入、工具准入、审计、配额、成本。

**动手实验**

- 用第 24 章的 FastAPI + MCP 代码，做一个 `get_alerts` / `search_runbook` / `create_ticket` 三个工具的 Server；
- 让 Agent 完成一次"P2 告警 → 检索 Runbook → 给出处置建议 → 人工确认"；
- 记录完整 trajectory（每步输入/工具/结果/耗时）。

**交付物**：可运行的 Agent Demo + 一次完整轨迹 + 评测集（20 条）。

**自检**：能否解释"为什么写操作必须审批 + 幂等"？

### 第 7 周：RAG 与知识工程

**目标**：搭一个能回答运维 Runbook 问题的知识库，并给出评测结果。

**知识点**

1. 文档解析：PDF/表格/扫描件/代码；
2. 分块：按结构而非固定长度；
3. 混合检索：BM25 + 向量 + 元数据过滤 + Rerank；
4. 引用与权限继承；
5. 分类体系（业务域/文档类型/生命周期/权限域）；
6. 知识质量：准确性、时效性、完整性、可用性。

**动手实验**

- 用 20–50 份 Runbook/FAQ 建库；
- 对比"纯向量"与"BM25 + 向量 + Rerank"的 Recall@5；
- 建 30 条 Golden Questions，测答案正确率与引用准确率。

**交付物**：检索评测表 + 一页结论（哪种组合最好、为什么）。

**自检**：能否解释"为什么企业知识库不能只用向量检索"？

### 第 8 周：产品化与综合项目

**目标**：把前 7 周的能力组装成一个可演示、可度量、可答辩的项目。

**知识点**

1. 愿景与用户旅程；2. 价值-成本矩阵与 RICE；3. 采纳度指标；4. 推广与反馈闭环；5. ROI 计算。

**综合项目（二选一）**

- **项目 A：DC 巡检 Copilot** —— 定时巡检 → 异常检测 → 生成报告 → 建议工单；
- **项目 B：告警 RCA 助手** —— 告警收敛 → 拓扑关联 → 知识检索 → 根因假设 → 人工确认。

**交付物**：架构图 + Demo + 指标看板 + 10 页答辩材料 + 3 分钟演示视频。

#### 五、计算题（2 题 × 10 分 = 20 分）

1. 某机房 IT 负载 100kW，PUE = 1.25，电价 0.6 元/kWh。求总功率与年电费。
2. 某冷板液冷系统带走 80kW 热量，供回水温差 ΔT = 10K，水的比热容取 4.18 kJ/(kg·K)。求体积流量（L/s 与 m³/h）。

#### 参考答案与评分点

**单选**：1-B　2-B　3-A　4-B　5-B　6-B　7-B　8-B　9-B　10-B

**多选**：1-ABCDE　2-ABCD　3-ABCD　4-ABCD　5-ABCDE

**判断**：1-错（混合方案）　2-错（NVLink 限于机内/超节点）　3-错（需兼容矩阵）　4-对　5-错（需持续/定期验证）

**简答 1 要点**：清单 → 版本矩阵 → 采集 → 漂移检测 → 灰度升级 → 回滚 → 审计（答出 5 个即满分）。

**简答 2 要点**：单卡（nvidia-smi/DCGM）→ 单机多卡（nvbandwidth/nccl-tests）→ 多机网络（ib_write_bw）→ 端到端模型（吞吐/延迟）→ 72 小时稳定性与基线对比。

**简答 3 要点**：功率分解 → PowerShelf 48V/50V → N+N 冗余 → 冷板液冷 + 风冷融合 → CDU/SideCar → 漏液检测/快接头/双路供水 → PUE/WUE。

**计算 1**：总功率 = 100 × 1.25 = **125 kW**；年电量 = 125 × 8760 = **1,095,000 kWh**；年电费 = 1,095,000 × 0.6 = **657,000 元**。

**计算 2**：`Q = P/(c_p·ΔT) = 80/(4.18×10) = 1.914 kg/s ≈ 1.91 L/s`；换算 `1.91×3.6 ≈ 6.89 m³/h`。

## 5. 高频追问 Q&A（20 题）

**Q1. PowerShelf 和传统服务器 PSU 有什么区别？**
传统 PSU 是"每台服务器各自 AC→DC"，转换损耗分散、线缆多、维护颗粒度细；PowerShelf 是"机柜级 AC→48V/50V DC"，统一供电、效率更高、支持 N+N 冗余与热插拔，适合高密机柜。代价是机柜级单点风险更高，必须做好冗余与配电设计。

**Q2. 冷板液冷漏液怎么防？**
①快接头 + 双密封；②漏液检测绳/传感器，分区告警；③CDU 压力/流量/液位监控；④负压设计（部分方案）；⑤定期巡检与保压测试；⑥漏水时自动切断对应支路。**不能只靠"买好管子"**，要有检测 + 隔离 + 演练。

**Q3. 风冷和液冷怎么配比？**
按热流密度算：GPU/CPU 用冷板，内存/网卡/电源仍靠风冷，形成"风液融合"。比例取决于单柜功率、器件热流密度、机房条件；通常高密 GPU 机柜液冷承担 70%–90% 热量，剩余由风冷带走。最终以厂商热设计文档与实测为准。

**Q4. 机柜承重和抗震要注意什么？**
满载 GPU 服务器单柜可达 1–1.5 吨甚至更高；要核算楼板承重、机柜底座、抗震支架、运输与吊装；液冷还要考虑管路重量与振动。**设计前必须拿到机房结构图纸与承重余量**。

**Q5. CMDB 数据不准怎么办？**
①自动发现（Redfish/网络扫描/Agent）替代人工录入；②唯一 ID 与生命周期状态机；③变更联动（工单关闭即更新）；④数据质量评分与定期稽核；⑤"谁维护谁负责"的 owner 机制。**先把核心关系（设备-机柜-网络-业务）做准，再谈 AI**。

**Q6. 告警风暴怎么处理？**
拓扑聚合 + 时间窗 + 因果抑制 + 去重 + 分级。先判断"是不是同一个根因"（同交换机/同电源/同机柜），再做抑制；同时限制通知渠道（只推 P0/P1），避免刷屏。

**Q7. 数字孪生在运维中的价值是什么？**
把机房/机柜/设备/管路/网络建模成可计算的虚拟副本，用于：容量模拟、变更影响分析、故障演练、液冷流量/温度仿真。**价值在"提前验证"，不是"好看"**。

**Q8. 变更风险评分怎么做？**
特征：变更类型、影响设备数、是否核心业务、历史失败率、是否首次执行、回滚难度、时间窗口。用逻辑回归/GBDT 或规则打分，输出"低/中/高"；高风险强制审批与灰度。

**Q9. AIOps 模型误报太多怎么办？**
①先做规则与阈值基线；②用多指标联合判定（而非单指标）；③引入"持续时间/趋势"条件；④按业务分级告警；⑤持续用人工标注反馈训练；⑥设置"观察期"而不是立即告警。

**Q10. 慢卡怎么发现？**
同型号基线对比：带宽、算力、温度、功耗、ECC、NVLink 速率；用 `nvbandwidth`/`nccl-tests` 定期抽检；训练任务里看 step time 分布。发现后隔离、复测、返修。

**Q11. Agent 工具设计的原则？**
单一职责、动词命名、参数少而明确、返回结构化可截断、超时与幂等、权限最小化、错误码稳定、可审计。

**Q12. 长任务 Agent 怎么恢复？**
状态机 + 持久化 checkpoint + operation log；崩溃后从最近可信状态恢复；副作用操作要有幂等键；恢复前先判断"上次操作结果是否未知"。

**Q13. 记忆污染怎么防？**
只写可验证的事实；写入前做去重与置信度评估；设置 TTL；保留来源与版本；提供人工纠正入口；定期审计。

**Q14. 评测集怎么构建？**
从真实业务抽取 + 人工标注 + 边界/对抗样本；分层（Golden/边界/对抗）；每次线上失败补入；定期更新，避免过拟合。

**Q15. RAG 表格问答怎么做？**
表格结构化解析（行列/表头/合并单元格）→ 转成结构化记录或"表头+行"文本 → 元数据过滤 → 必要时用 Text-to-SQL；不要直接把表格拍平成一段文本。

**Q16. RAG 权限继承怎么做？**
文档级 ACL → 检索时按用户权限过滤（元数据/向量库过滤）→ 生成前再次校验 → 引用只展示有权限的片段。**不能只在应用层做一次过滤**。

**Q17. 增量索引与删除怎么做？**
用文档版本号/更新时间做增量；删除要同步删向量与缓存（软删 + 定期清理）；Embedding 模型升级要重建索引并做双写/切换。

**Q18. 平台冷启动怎么推广？**
选 1–2 个高频高痛场景做样板间，拿到量化收益（节省工时/降低 MTTR），再做内部分享、培训、激励；**不要一上来就全公司推**。

**Q19. 怎么量化 AI 平台的 ROI？**
`ROI = (节省人力成本 + 降低故障损失 + 提升资源利用率收益 − 平台与模型成本) / 投入`。要能拆到场景级：每个场景节省多少工时、减少多少故障时长、提升多少利用率。

**Q20. 行为面试怎么用 STAR？**
Situation（背景与规模）→ Task（你的目标与职责）→ Action（你做了什么关键决策）→ Result（量化结果）。**重点讲"你的决策"和"取舍"，不要只讲团队做了什么**。
